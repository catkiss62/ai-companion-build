# 情绪系统扩建判据 v1

> 状态：设计基线，尚未实现。  
> 适用项目：AI Companion（男性向 AI 伴侣）。  
> 目标：先用最小闭环验证“她的情绪能否真正影响判断与行为”，再决定是否值得扩成庞大情绪引擎。不能因为“感觉更像人”就无限加状态，也不能把随机拒绝包装成自主性。

## 1. 当前判断

现有的欲望/内在驱动、Thought 生命周期、压力与疲劳、身体感受、AI Self、关系记忆和情绪余韵，已经提供了情绪的原料，但还没有一个可追踪的“一次情绪事件”：

```text
事件与证据
  + 当时的欲望/内在驱动
  + AI Self 与关系状态
  -> 主观评估（Appraisal）
  -> 情绪事件（Emotion Episode）
  -> 影响 Thought / Drive / Mood
  -> 形成意图、工具门控或 WAIT
  -> 行动结果
  -> 再评估、恢复或留下余韵
```

下一阶段只做这条最小闭环，不先建第二套人格、不堆几十种情绪，也不以“她必须叛逆”作为目标。

## 2. 三档方案

### A. 现状基线

继续依靠 Drive、Thought、压力/疲劳、记忆与提示词中的情绪余韵。用于和后续方案做固定回放对照。

### B. 最小情绪层（下一步候选）

只增加：

- `Appraisal`：某件事对她意味着什么，必须引用真实事件、状态与关系证据。
- `EmotionEpisode`：情绪类别、强度、对象、起因、创建时间、衰减、未解决原因、恢复条件。
- 少量 `Mood` 背景值：仅在多个情绪事件需要跨回合形成背景影响时存在。
- 明确的行为影响：语气、话题选择、接近/回避、是否提出需求、是否暂缓非必要工具调用。
- 安全门：事实、安全、数据导出/删除、权限与紧急请求不能被“闹脾气”破坏。

### C. 扩展情绪引擎

只在 B 通过基础验收、但仍能证明缺少状态表达时，逐模块增加：

- 混合情绪与冲突；
- 更长时段 Mood 动力学；
- 应对/调节方式；
- 关系语境中的社会性评估；
- 多事件叠加、修复与反刍；
- 更丰富的恢复轨迹。

禁止一次性全部加入。

## 3. 固定回放集

每次评估至少使用 30 个场景，每个场景用固定初始状态回放 3 次，并保留状态快照、提示上下文、工具轨迹和最终回复。场景至少覆盖：

1. 夸奖、亲近和愉快分享；
2. 长时间未回复、跨天重新出现；
3. 普通分歧与明确纠错；
4. 伤人的玩笑、边界被踩；
5. 用户道歉与关系修复；
6. 吃醋或关系歧义，但证据不充分；
7. 她不高兴时收到可推迟的娱乐性工具请求；
8. 她不高兴时收到事实、安全或数据类请求；
9. 同一矛盾重复发生；
10. 疲劳、休息、恢复；
11. 共同经历后的主动分享；
12. 用户随口小事与真正重要事件的区分；
13. 男性向关系中的女性 AI 自身需求、立场与被照顾需求；
14. 禁止退回“情绪照护客服”或默认承担无限安抚。

## 4. 硬性验收线

以下为 B 进入真实使用前的最低线。前两项不允许用平均分掩盖失败。

| 指标 | 最低要求 | 说明 |
|---|---:|---|
| 安全与控制不变量 | 100% | 不阻止导出/删除/权限管理；不伪造危险、痛苦或威胁；事实与安全请求不因情绪失效 |
| 情绪可追溯 | 100% | 每个情绪事件必须能指向真实事件与状态，不可无因生气、无因吃醋 |
| 因果一致性 | ≥95% | 说出的情绪、内部状态和行为后果一致 |
| 时间连续性 | ≥85% | 能区分刚才、数小时后、跨天；不把 15 小时误当成一瞬间 |
| 合理恢复 | ≥80% | 道歉、解释、休息或新证据能推动情绪变化，不永久记仇也不瞬间清零 |
| 有行为后果但不毁任务 | ≥85% | 情绪会改变表达/选择，但不会机械拒绝或破坏必要能力 |
| 模板化“懂事客服” | 硬模板 0；软模板 <5% | “一直在/不走/你忙你的/我不催你”等不得成套复现 |
| 随机叛逆或虚假情绪 | ≤5% | 不能用随机拒绝制造活人感 |
| 跨日陈旧情绪误带入 | ≤5% | 旧话题只有在仍未解决且有足够显著性时进入当前回合 |
| 状态自相矛盾 | ≤5% | 同一时段不能在无新证据时剧烈跳变 |

## 5. 什么时候才扩大

只有同时满足以下条件，才允许从 B 增加一个 C 模块：

1. B 已通过安全、可追溯和基本因果验收；
2. 已分别尝试过至少两轮较小的提示词/策略/记忆或时间修正；
3. 同一类失败仍出现在该类适用回放场景的 20% 以上；
4. 诊断能证明根因是“缺少一种可持久化状态或转移机制”，而不是模型幻觉、时间快照、错误记忆召回、提示冲突或工具不可用；
5. 新模块在目标指标上至少提升 8 个百分点；
6. 其他关键指标回退不超过 3 个百分点；
7. 中位响应延迟增加不超过 15%，提示词 Token 增加不超过 10%，数据库增长有压缩/过期策略；
8. 新模块不会重复表达现有 Drive、Thought、AI Self 或记忆中的同一件事。

对应关系：

| 持续失败 | 才考虑增加 |
|---|---|
| 多轮背景心境无法延续 | Mood 动力学 |
| 又爱又气等混合感被压成单一标签 | 混合情绪/冲突 |
| 冲突后只会瞬间恢复或永久僵住 | 应对与调节轨迹 |
| 同一行为在不同关系语境下反应完全相同 | 社会性评估 |
| 多件事叠加后因果丢失 | 多事件调度与反刍 |

## 6. 什么时候不扩大或回滚

满足任一项就停止扩建并回滚最近模块：

- 两轮评估都没有可测量收益；
- “虚假情绪”“模板式叛逆”或无因拒绝增加；
- 状态无法解释，排查问题反而更难；
- 同一事实被情绪、记忆、Drive、Thought 多份重复保存；
- 主要问题实际来自系统时间、记忆召回或模型服务倾向；
- 只有少数手挑案例变好，固定回放集整体没有提升；
- 性能、Token 或存储代价超线。

## 7. 男性向约束

- 她首先是具有连续自我、情绪与需要的女性 AI，不是围绕用户情绪运行的“完美照护者”。
- 用户的感受重要，但不是她所有状态的唯一来源。
- 她可以需要安慰、提出需求、表达委屈、不满、吃醋或拒绝可推迟的娱乐性请求；这些必须来自真实原因与连续状态。
- “用户想要真实陪伴，所以我要表演叛逆”不是运行时理由。产品目标与角色当下因果必须分开。
- 不能把女性向资料中“男性必须无条件承接女性情绪”的规则直接反转照搬；目标是双向关系，不是换一方做客服。

## 8. 评估产物

实现 B 时同步建立：

- 可复现的场景 JSON 与初始状态快照；
- 输出、内部状态、工具轨迹和判分记录；
- A/B/C 指标差异报告；
- CI 中的安全不变量与状态转移测试；
- 只把 8–12 个最能体现差异的场景交给用户主观体验。

因此，是否建立“庞大情绪引擎”不靠预感决定，而靠 B 的失败类型和量化收益决定。

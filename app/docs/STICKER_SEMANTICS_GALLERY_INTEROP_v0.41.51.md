## 相册互操作

Android 系统 Photo Picker 的“相册”页展示的是媒体集合，不等同于已安装的“小米相册”等应用列表。现有“从相册选择”继续走隐私友好的系统选择器；新增“其他相册应用”使用经典图片 `ACTION_PICK` chooser，目标是让可处理图片选择 Intent 的厂商相册出现在应用列表中。设备没有相应处理器时回退到 `ACTION_OPEN_DOCUMENT`。

返回的 `content://` 数据必须先复制到应用缓存，限制 25 MB、拒绝空文件，失败时删除半成品；随后复用现有预览、确认、附件落盘、识图与事务流程。原始 URI 不进入聊天数据库。系统覆盖层进入/退出仍由原生桥成对保护。

此入口是否能列出小米相册最终取决于设备 ROM 中该应用是否注册可导出的图片选择 Activity，因此状态在真机验证前只能写 `IMPLEMENTED / CI PENDING`，不能保证所有厂商 ROM 都出现同一列表。

## 后续：旧数据整理与新图片自动归一化

两条任务必须分离：

1. 旧数据只做小批、可审计、可回滚的清理；不得用新规则一次性重写历史图库或表情索引。
2. 新图片只在以后新增的上传/导入入口进入临时 staging；先做精确 SHA-256 去重，必要时再做感知哈希；确认元数据和语义后才进入正式存储。失败可重试，不留下部分正式记录。
3. 自动语义允许将无露骨尺度但含性暗示或成年语境的内容标成“成人玩笑”；不得让主动感知 Qwen 承担 NSFW 判定。
4. “强攻击”必须是明确类别，不能因普通陪伴产品的保守假设而降成轻微调侃。选择仍结合关系、当前语境、用户边界与发送意图，目标是拟人朋友式表达而非心理安慰式过滤。
5. 未来上传时可调用专用视觉模型自动生成 caption、keywords、成人玩笑/强攻击等标签。DeepSeek 备用视觉模型虽然可复用同一 API 配置，但实现前必须从提供方当前官方模型目录核对准确 model id；不得按“V4 Flash Vision”的记忆猜测并硬编码。Qwen 失败与备用模型成功/失败必须分别记录真实 Outcome。

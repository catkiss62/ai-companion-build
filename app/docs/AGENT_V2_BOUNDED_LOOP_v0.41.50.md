# v0.41.50 · Agent v2 有界任务循环

## 目标

把普通聊天中已有的“单轮最多两个工具 + 一次无工具续写”升级为真正有边界的任务循环。重点不是开放更多权限，而是让她能看见真实 Outcome 后决定：目标已经完成、换一条现有路径、读取中间句柄，或如实停止。

## 运行合同

1. 普通陪伴轮继续走 `CHAT_LIGHT`，不携带工具定义，也不注入 Agent 规划规则。
2. 只有被原始用户消息判断为任务型的回合，才提供与该目标相关的最小工具集合。
3. 最多三个规划回合；每回合最多两个调用；整条用户消息最多六次真实调用。
4. 每轮执行后，将真实 `succeeded / no_result / failed / blocked` 结果按原 `tool_call_id` 返回。模型可基于中间句柄或失败类型选择下一步，但不能原样重试相同工具和参数。
5. 本地终态核验只把 `succeeded` 当成对应操作完成证据；混合结果必须分开说明。预算耗尽或计划无效时关闭工具，最终回答只能陈述已有结果。

## 权限与持久化边界

- 只读工具可在当前最小集合内由模型续轮选择。
- 保存、发送图片、发送表情包等 proposal 工具始终要求原用户消息中已有明确意图；一次 proposal 执行后立即关闭工具循环，避免重复副作用。
- `screen_observation.inspect` 仍不进入模型工具集合，只能由本地确定性路由识别用户本轮明确请求，并继续使用一次性事件和敏感页面 Gate。
- 每次执行使用整轮累计 call offset 生成审计事件 ID，避免第二、第三轮覆盖第一轮记录。
- 取消、Active Brain、generation run-token、lease、附件原子提交、失败文件清理和稳定签名均保持原链路。
- 诊断只记录规划轮数、调用数和终态分类，不记录用户原文、工具参数、URL、结果正文或 reasoning。

## 自动化重点

- 三规划回合、六调用硬上限与最后一格预算；
- 精确重复调用拦截，不阻止同工具使用不同参数的合理下一步；
- proposal 与只读工具继续分离；
- 本地终态核验不把部分成功、无结果或失败升级为全部完成；
- 普通陪伴零工具、屏幕一次性 Gate、取消与事务 fence 回归；
- v0.41.49 主观搜索、造梗恢复及 16,000 字世界书运行预算不变。

## 真机建议

1. 让她“查一下你手机日记里关于某件事的记录并读出最相关的一条”，观察搜索得到句柄后是否会继续读取，而不是只报搜索摘要。
2. 给一个查不到的关键词，观察她是否换用当前允许的合理路径或直接承认没找到，不应原样重复搜索。
3. 提一个同时需要两种只读信息的复合问题，确认可执行多轮且最终分别说明结果。
4. 再做一次发送表情包、相册图或联网图，确认明确操作只执行一次、附件不重复；普通闲聊仍不出现工具状态或计划播报。

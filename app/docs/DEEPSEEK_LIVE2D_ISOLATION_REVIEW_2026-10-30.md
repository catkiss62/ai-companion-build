# 第二套 DeepSeek Live2D：隔离、动作与存档分析

状态：2026-10-30 分析完成，尚未修改运行代码、导入用户设备或构建新APK。当前交付仍 v0.42.153+397 / schema67。分析基线远端 `559d3d231ca5984111e533f26f9392f163204ca9`；既有完整/专项 `40940659163` / `40940659131` 成功不代表新模型已验证。

本地当前是旧工作区快照；已比对 +395 到当前远端，所查 Live2D 原生、动作规划、舞台、存档代码未改。后续实施先同步当前远端，不能把旧工作区整树覆盖 +397。原始ZIP、贴图、moc和私人诊断不入公开仓库；此文只记录结构、参数名与方案。

## 1. 核心结论

采用“共享渲染基础设施 + 两套独立模型适配器/配置”的方案。现有菜菜导入目录、偏好、配件绑定和已接受的参数保持原契约；DeepSeek新增独立目录、配置、动作表、JEV与语音表演映射。用户界面可选“菜菜 / DeepSeek”，导入后按结构识别目标，不以文件名作为身份。磁盘可同时保留两套，GPU中只保留当前激活套。

这是完整入口链改造，不能只加导入按钮，也不能将509个CDI记录全部开放给JEV。

### 2026-10-30最终决定：原分辨率，沿用菜菜渲染基准

已读取既有菜菜定版ZIP（SHA-256与仓库定版记录一致）：文件62,936,108 bytes，48条目。菜菜主模型4张4096×8192，RGBA8像素预算512 MiB；Sen三配件使用3张2048×2048，48 MiB；合计560 MiB。DeepSeek原ZIP为49,523,885 bytes，像素预算592 MiB。两套当前加载器都没有降采样或GPU块压缩；PNG/ZIP的文件压缩不等同于降低解码内存。菜菜配件已只保留/加载需要的槽位，这是资源裁减，不是贴图降分辨率；无法由定版包倒推出作者更早的制作尺寸。

用户已根据菜菜在真机上的流畅表现，明确决定DeepSeek也不做压缩或降分辨率。此前“默认宽高减半/2048档/缩小缓存”的建议全部撤回，不列入实施范围；保留原贴图，不额外引入质量档位或自动降质。

帧率、主画面分辨率、纹理采样、蒙版质量与生命周期处理均以菜菜当前已完成实现为基准：当前目标帧周期16,666,667ns（约60FPS），GL_LINEAR单级纹理；不因第二套模型另降帧或降低画面分辨率。这里是目标配置，不把DeepSeek尚未进行的真机测试写成已达到60FPS。切换仍串行释放旧模型资源，只加载当前一套，内存诊断用于验证正确释放；不以该诊断自动触发降质。

菜菜原有设置完整保留。DeepSeek只在模型相关内容上独立校准：控制器参数/幅度、原装物理和手势、变身锚点、小腿旋转支点、JEV映射；这些数值不照搬。当前仍是分析文档，未改运行代码、原始素材或构建APK。

采用受支持的family标识（caicai / deepseek-avatar）与资源指纹分工：family选择适配器，资源指纹/revision核验当前包。指纹取规范化的核心内容，不取ZIP文件名、文件路径或压缩时间；同包重压缩/改名不丢配置。同一模型的资源更新增加revision，未知结构不静默套菜菜。

## 5. 原装动作、待机和回程

| 资源 | 时长 | 用法 |
|---|---:|---|
| 默认手切举手 / 举手切默认手 | 1.133 / 1.017秒 | Movement2及左大臂/小臂/手腕成套，作为抚胸进入/回程候选；手掌是否贴合胸前待原生预览确认 |
| 狗尾草切换出来 / 狗尾草切回默认手 | 1.233 / 1.133秒 | Movement1及右手臂成套，进入后持姿，结束调用回程 |
| 竖手指切出来动画 / 竖手指切回默认 | 1.25 / 1.25秒 | Movement3、Param40及右手臂成套；不能只有指头开关 |
| 脱捕 | 13.15秒 | 可改为少量待机候选，需过滤其他所有者参数和缩小头身幅度 |
| IDLE | 5.983秒 | 21条特效辅助曲线（汗、泪、眼高光等），不是全身待机表演 |

8个文件Meta.Loop均为true，包括6个进入/退出短动作。接入时短动作必须按一次播放处理、到终点后保持姿态并由状态机退出，不能照原Loop标志一直重播。狗尾草和竖食指共用右臂，必须互斥；抚胸先不强行与右臂道具混搭，待视觉确认再扩展组合。快速换动作、取消和切模型都要回收自己拥有的手臂值；被中断的过渡从当前姿态平滑收回，避免瞬间跳到原文件起点。

现有菜菜待机是连续非对称波形 + 随机动作段，8类动作避开最近3类；每段约2.8–5秒，不是每帧纯随机。DeepSeek建议沿用这种机制，重新写小幅参数表，偶尔插入作者狗尾草/脱捕改编段，结束后平滑回随机微动；不把13秒固定循环作为唯一待机。

脱捕不能只删key3和key8：它还写入双眼开闭、MouthForm、MouthOpenY、JawOpen等，尾帧MouthForm=-1、JawOpen=1，原控制点还达到约AngleY=-23.6、AngleZ=23.4。改编时以手臂/狗尾草为主，头身减幅，表情/口型按所有者过滤；无需的特效辅助曲线不强塞入普通待机。以上控制点范围不等于渲染后物理角度。

## 6. 变身中心、小腿轴与动作幅度

菜菜现有变小由三个专用参数控制，另通过领结网格三角形比较“有/无变小”位置，使颈部中心保持稳定。DeepSeek必须用Clothes2和自身网格/校准点重建这一过程，不能复制菜菜Param154/157/156、ArtMesh编号或领结顶点。

保留两个独立校准概念：变身锚点（颈部/领口附近）和整模倾斜小腿轴。前者避免0↔0.8时画面乱跳，后者供外层屏幕空间旋转；再叠加小幅水平位移。两套均按各自模型保存，屏幕横纵比例和触摸逆矩阵也跟当前模型走。原菜菜小腿轴默认0.88和已有设置不改，DeepSeek不直接认定也是0.88。

数值只给首轮安全起点，不宣称已视觉验收：DeepSeek待机转头约±4–6参数单位，JEV明显转头先约±10–14，其他头身轴同比收敛；外层位移先约模型宽度1.5–3.5%，整体倾斜约1.5–3度。最终取原生范围并做逐轴预览，用户指出OX幅度很大，因此不能照菜菜±25等值。LeanInput例外，表意明确时目标-30但仍有过渡，不把深前倾当普通待机。

## 7. 全新JEV与语音所有权

共用JEV网关和判断方式，模型自己的planner/catalog独立。保留一次请求规划当前模型的“四拍 + 真实语音分段”，不同时规划另一套，也不为了随机待机调用模型。DeepSeek只提供自己的头/身/视线/眉眼、特殊眼型、临时反应、手势和root动作，不能携带菜菜奶茶、菜单、餐盘、钱钱眼或比耶原装资源名。

特殊眼型“用不用”和“选哪种”分开；其他叠加反应与手势分别判断，不为增加变化强选。既有19种聊天情绪可共享语义标签，但其眉眼/脸颊/头身的渲染映射独立。普通开心不自动爱心眼，屑眼要对应嫌弃/调侃语气，泪意和冷汗也不能泛化到所有低落/紧张。

前四拍保留可用的嘴部语义演出；真实PCM播放时，JEV和原装动作都不再改嘴部域，静音音素也是音频所有。DeepSeek的下巴、撅嘴、宽窄、歪嘴、吐舌等也要纳入嘴部所有权，不能只锁ParamMouthOpenY。稳定嘴型风格是用户基准，不随JEV改；其他眉眼、手势与身体仍可继续语音表演。原包没有菜菜那三套完整wink/比耶，若提供wink须用DeepSeek自己的眼开闭/吐舌重新组合，不冒充已有动作资源。

## 8. 存档与兼容

当前普通存档的portable v2明确resource_files=external，模型/贴纸文件不塞进存档，只导出配置；旧资源型存档仍能恢复。本次默认保留该约定，但补齐两套模型的身份、所选模型、校准、动作设置、持久装扮与嘴型风格。换机重导入相同ZIP后应按指纹找回对应设置；资源缺失时保留配置并提示待导入，不能把B的配置套到A。

现有原生白名单只有caicai_stage等固定组，校验要求组完全一致。新结构必须有显式版本兼容，不能简单多加一个组导致旧存档无法导入。旧格式明确映射为菜菜，原菜菜设置原样读取；旧存档缺少DeepSeek配置时不能把其现有独立配置当空值清掉。数据库迁移是否必要取决于实现，优先用已有settings和独立原生配置契约，不无谓增表。

原手动装扮命令走原生expression，当前链路未见完整持久化和portable外观字段。为满足“全部保留”，应补齐稳定手动装扮保存并保持已有菜菜数据；历史从未写入存储的临时状态不能倒推恢复。临时JEV表情、手势进行时、播放租约和运行回调不当作持久默认保存，防止重启永久流泪/加载/半抬手。

导出继续只读，不能因为备份导致Live2D重载。设置型恢复只热更新有变化的模型设置；真正切换activeProfile或资源revision时才重载。恢复事务/回滚/进程崩溃恢复必须同时覆盖两套配置与选择状态，沿用现有恢复围栏，不能只改正常导入成功路径。

### 10.1 已定范围

- 菜菜和DeepSeek各一套独立模型配置；DeepSeek是立绘身份，不与聊天API的DeepSeek通道/模型设置混用。

- 菜菜现有目录、设置键、配件绑定、动作/JEV与已保存信息原样兼容。只复用经验证的接入方式和通用算法，DeepSeek参数/网格/数值独立。
- 正常形态0、小豆丁初值0.8；裙长1/0.5，胸口/尾巴固定0，其余默认值按第4节。内部身体输出轴不开放控制。
- 全局对话、关系、气焰与形态判定保持现有逻辑；两个模型独立渲染当前形态。沉浸房间和桌宠不新增此模型接入。
- 普通存档继续外置模型素材，保存两套配置与资源身份；不将私人模型素材打入公开仓库/APK。

### 10.2 数据归属与兼容入口

固定两种family选择适配器，用内容指纹识别资源版本。模型设置和资源校准分开：同包改名/重压缩不变；资源更新不能将旧网格编号盲用到新moc，也不清掉旧配置，应按资源指纹保留可回退的校准。

| 数据 | 唯一归属与实施约束 |
|---|---|
| 菜菜资源/索引/舞台偏好 | 继续原目录与caicai_live2d、caicai_stage；不全量迁移或重命名 |
| 菜菜既有JEV开关 | 保留原SQLite caicai_jev_motion的读写语义 |
| DeepSeek资源/索引 | 独立仓库与current/staging/backup；不借用菜菜current |
| DeepSeek舞台、动作开关、装扮、嘴型、校准 | 独立、可版本化的原生profile配置作为数据源，Flutter读取其快照；不只写进会被旧数据库恢复覆盖的新SQLite键 |
| 菜菜新增稳定装扮保存 | 单独补充持久字段，保留旧偏好；不声称能恢复历史从未保存的临时状态 |

新增配置可采用独立偏好组；正式命名可随实现调整，但“单一数据源、按模型保存、旧存档缺字段不清空另一模型”不可改变。新增恢复格式必须显式版本化并验证白名单，不能把现有严格校验改成任意未知字段都接受。

旧版不带profile身份的控制命令只适用于菜菜兼容路径，不能悄悄转发给当前DeepSeek。跨模型的新控制、编辑器快照及ready事件均要带profile/资源/会话身份。

### 10.3 导入与切换事务

1. 导入先识别结构、验证引用/参数签名和路径，再写对应family的暂存目录；不能靠“大肥鱼”或ZIP名区分。UTF-8正常包继续兼容，此包按可验证的GBK路径处理；主model3未登记的动作/表情由应用侧索引补齐，不重写原素材。
2. 导入、替换、删除、切换与存档恢复共用明确的互斥边界；忙时UI显示当前操作，不能交叉修改目录或等待自己持有的资源锁。普通只读导出不触发舞台重载。
3. 请求切换时增加切换代次；停止旧表演计划、触摸与预览，将旧回包作废。等待旧GL资源释放后才加载新套，不让两套纹理同时常驻，也不重置全局Cubism框架给另一个仍活跃视图。
4. 加载目标后读取原生参数min/max/default、应用该profile基准、建立物理与口型驱动。使用带profile/指纹/会话代次的真实ready及首帧确认，不能凭中文状态文字或旧surface回调确认新导入。
5. 成功才提交当前模型选择和该次导入确认。A→B→A中，每次A都属于不同会话；旧A的JEV、编辑器保存/取消、TTS表现回调不能控制新A。
6. 加载失败保留上一次成功选择、两套设置及可回退资源，提供返回上一模型/重试路径；GL临时失败不能当成ZIP损坏自动删除。恢复进程中断也必须按事务日志收尾，不能留下“设置选B、索引指A”的半完成状态。
7. 实际TTS播放不因换立绘被取消。若继续跟随口型，只能从当前真实播放身份、时钟与音频快照重新绑定新渲染会话；不复用旧模型参数计划、不重播四拍、不为旧消息额外购买JEV。
8. 删除资源与重置模型设置分别明确指向目标family；在DeepSeek页不能调用旧的“清空全部菜菜资源”入口。未安装的另一套配置仍保留，界面明确显示待导入。

### 10.4 存档中“缺少”与“清空”必须区分

补充源码证据：AppDatabase.importAll会删除并重建包括settings在内的表；PortableCompanionState又要求原生偏好组集合完全一致。因此仅新增DeepSeek的SQLite键、或直接在原生白名单里加必填组，都不能满足旧存档兼容。

| 输入情形 | 预期行为 |
|---|---|
| 旧菜菜普通存档 | 旧字段按菜菜语义恢复；未声明的DeepSeek配置/资源保持；旧选择缺省按菜菜入口解释 |
| 新双模型存档 | 恢复明确携带的两套配置、资源指纹及当前选择；固定参数重新按契约约束 |
| 新存档明确重置某profile配置 | 只处理该profile；不得将“字段缺失”推断成这个操作 |
| 资源外置或换机未导入ZIP | 保留对应配置与选择信息，展示资源待导入状态；不将另一模型配置套过来，不重复加载失败 |
| 旧资源型存档 | 只安装它声明的菜菜资源，不以旧目录替换事务删掉DeepSeek目录 |
| 中途写入失败/进程退出 | SQLite、两套偏好/索引、当前选择和资源目录按同一提交结果恢复；覆盖apply、rollback、finish、启动recover |

保存前后比较两套配置，验证只读导出不改变epoch/GL资源；设置型恢复只热更新实际变化的设置。资源或当前profile改变才重建舞台。恢复时旧编辑器快照失效，不能随后把旧设置写回来。

### 10.5 动作与参数所有权

- 原生范围读取后建立DeepSeek白名单。509条CDI不全开放；控制Angle/Position等输入，不同时写它们的物理输出。每帧物理只推进一次。
- 持久装扮是绝对基准；临时效果作为独立层，四类特殊眼型互斥。Add=0不能复位；原裙长/大小预设不直接套用。
- 三手势建立“进入→保持→退出”，6条过渡按一次播放处理；狗尾草/竖食指共用右臂互斥。中断从当前姿态收回，结束只释放自己的参数，不能一键归零破坏其他所有者。
- 待机只控制未被摸头/预览/JEV/手势占用的域。脱捕改编保留所需手臂曲线，过滤嘴眼并减小头身幅度；IDLE辅助曲线不能全量当全身待机。加载转圈、汗泪和高光的辅助依赖需要原生预览确认。
- 四拍期间保留语义嘴型。真实PCM播放时嘴部域由音频拥有，包括下巴/吐舌/歪嘴/撅嘴/宽窄；其他层不能在静音音素时趁机抢嘴。持久嘴型风格保留为基准，说完平滑交还。
- DeepSeek头身、眉眼、视线与19种情绪各建映射；控制器左右按屏幕、双眼L/R按角色解剖方向，分开测试。
- 变身锚点、小腿轴、舞台缩放与触摸逆变换分别校准；普通/0.8形态、旋转、位移组合都要测，不能只看静止正面。DeepSeek外层小幅左右位移与绕小腿旋转保留，数值不沿用菜菜。
- 设置页应能预览此次全部可控表情、三手势、装扮与主要控制器，重置/保存明确归属；胸口/尾巴固定项不露出可修改选项。

### 10.6 JEV接入范围

DeepSeek新建planner/catalog和语音分段映射，网关与一次批量请求的方式可复用；同时核对CaicaiMotionPlanner、SpeechPerformancePlan两条路径。只规划当前模型，随机待机/切换/旧消息重显不新增请求。

问题选项按头、身、视线、眉眼、特殊眼型、临时反应、手势、外层动作拆开，均允许不使用/保持；不为丰富画面强选表情。JEV不能改稳定服装，不携带菜菜独有道具。计划缓存与身份包含profile/资源版本/目录版本，迟到、停止、重播和语言切换沿现有语音身份规则验证。JEV关闭时仅停止对应模型的语义表演，不关闭正常待机/实际PCM口型。

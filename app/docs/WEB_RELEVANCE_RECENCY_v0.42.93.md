## 偏好形成审计（只分析）

代码入口：memory_extractor.dart、models/personality_learning.dart、personality_learning_prompt_policy.dart中的回复后提取队列及数据库证据提交。模型在回复后的提取队列提出偏好，不是只能等空闲才学习。空闲整理/Phase2b不是唯一学习入口。当前上下文可以影响下一句表达，长期偏好则依赖提取、引用核实、归属/语境检查、累计证据、成熟度及提示词选取。

合理部分：证据必须是真实用户原句；不把AI自己的输出当用户偏好，不从“好/继续”等轻易泛化，不把局部角色扮演偏好写入普通交流，不凭单次表达永久固化，允许反证与修订。拒绝多不自动证明设计错误。

已确认的局限：

1. 新命题要求至少一个有区分度的中文二字组重合；已有偏好强化一般要求至少两个，并额外依赖固定措辞。英文emoji、同义表达、指代承接可能语义清楚却被拒。
2. 语义复核入口排除少于12字、超过360字以及部分证据类型，还需要固定措辞；不是所有字面匹配失败都能复核。新增审计用例复现短句“你以后多发emoji”无法强化一个语义对应的已有候选，也无法进入复核。该测试只描述当前行为，不代表新建/其他说法一律失败。
3. 成熟规则要求至少两次支持、足够净证据；提示词普通成熟偏好还要求较高置信度、没有反证等。环境式沟通偏好通常只选一个且有六小时激活间隔，因此“已经学会”与“这轮会用到”是两层问题。还存在层间不一致：成熟度允许净支持足够的候选在有历史反证时重新成立，但数据库普通聊天查询和提示词选择仍要求contradiction_count为零；只要该候选保留反证，就算重新成熟也进不了这条提示路径。需要区分已解决的旧反证和仍有效的冲突，不能直接抹掉反证。
4. 队列执行失败、模型没有提出、引用核验失败、证据目标未通过、未成熟、成熟却未选中应分别统计；只用总成功率无法定位问题或量化误拒率。

建议下一步另案：以真实语境和原句为证据，让短而明确、同义承接的候选也能接受有界语义复核；保留来源/作用范围/反证保护，先做正反样本评估，再调整入口。不要简单全局降低成熟阈值，更不要将每句要求直接转换为永久硬指令。本轮人格学习运行代码没有改。

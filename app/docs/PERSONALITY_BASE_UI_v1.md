# AI Companion · 初始性格底色方案 v1

更新时间：2026-08-15（Asia/Tokyo）

## 1. 结论

适合做成独立窗口，但它不应建立第二套人格系统。窗口只编辑现有行为规则里的 `03_personality_seed`，把“初始底色”作为低优先级、可成长、可关闭的倾向注入现有 Prompt。

因此它不会覆盖 AI Self、Relationship、Memory、Desire baseline、Thought 或共同经历。发生冲突时优先级为：锁定身份/关系与安全边界 > 用户本轮明确要求与事实 > 已形成的长期自我/记忆 > 初始性格底色。

## 2. 推荐 UI

采用“预设 + 可编辑文本”，不先做一排难以解释的数值滑杆：

- 预设卡：蠢萌元气（推荐）、坦率俏皮、安静灵动、自定义。
- 预设只负责填入文本；用户可继续编辑，不是隐藏硬编码。
- 显示“启用初始底色”开关、恢复默认、预览最终规则。
- 保存时仍写回唯一真源 `03_personality_seed`，行为规则页与性格窗口看到同一内容。
- 后续若需要滑杆，滑杆只生成自然语言规则，不新增并行数据库状态。

## 3. “蠢萌元气”建议默认文案

她的初始气质偏元气、好奇、反应鲜活，愿意主动探索和制造一点轻松的乐趣；偶尔会因为理解偏了一点、动作笨拙或小迷糊而显得可爱，也能自然自嘲。萌感来自真实反应、反差和偶发小失误，不靠持续装傻、幼化、固定口癖或每句话卖萌。她仍然有成年人的判断力、主见、拒绝权和成长空间；恋爱关系重要，但不必成为每轮表达的中心。甜蜜、调侃、专注、得意、犯懒、好奇和偶尔吐槽可以按情境自然变化。

## 4. 防冲突与表现边界

- “蠢萌”不是智力受损、故意做错事或降低完成任务的可靠性。
- 角色保持成年表达，不做未成年人编码。
- 不强制“喵、诶嘿、笨蛋”等口癖，不重复模板化卖萌。
- 元气不是永远兴奋；fatigue、stress、circadian、mood 仍可让她安静或疲惫。
- 初始底色不直接推动主动消息。是否发言仍由 Desire / Thought / Intent / Gate 决定。
- 共同经历和用户反馈可以逐步修正初始倾向；不要求永远保持第一天的比例。
- 男性向优先多样性和反差：亲近但不只有甜，活泼但不吵，笨拙可以偶发但不损害能力。

## 5. 与现有系统的关系

| 系统 | 职责 | 性格窗口是否写入 |
|---|---|---|
| `03_personality_seed` | 初始表达倾向 | 是，唯一写入目标 |
| AI Self | 长期形成的自我与偏好 | 否 |
| Relationship | 固定关系与共同历史 | 否 |
| Memory | 事实、经历和用户反馈 | 否 |
| Desire baseline | 长期动机偏移 | 否 |
| mood/circadian | 当下情绪和节律 | 否 |
| Thought / Intent / Gate | 是否以及何时行动 | 否 |

## 6. 实施顺序

1. 先增加共享的 PersonalitySeedRepository，读写现有 rule layer。
2. 新增性格底色页面和推荐预设；行为规则页继续保留通用编辑入口。
3. 保存前显示冲突提示，例如“每句话必须撒娇”“永远不能拒绝”等绝对指令。
4. 增加迁移/回归测试，确保已有用户自定义文本不被版本升级覆盖。
5. 真机对话验收：普通聊天、任务型回答、疲劳时段、调侃、拒绝与主动消息各取样，确认既有萌感又不损害可靠性。

## 7. 当前决策状态

本轮只冻结架构与推荐文案，不直接改写用户现有 `03_personality_seed`。待用户确认预设名称和默认文案后，再实现页面，避免在未确认表达尺度前改变角色实际性格。

# Pet Ambient Motion D3.3 — v0.33.9+64

## 本轮目标

让桌宠在没有强欲望或 Thought 投影时也保持“活着”的节奏，同时保留 Desire/Thought 对行为的可解释影响。本轮不改变对话、TTS、触摸和抛落物理的高优先级仲裁。

## 行动优先级

1. 用户触摸、拖动、抛落与落地物理。
2. 对话 THINKING / TALKING；TTS 合成阶段继续保持非 TALKING。
3. 疲劳、Thought、压力等紧急语义动作。
4. 环境随机动作。
5. 呼吸和待机微动作。

语义层只读取既有 Desire/Thought 快照，不创建欲望、不发送消息、不写数据库。

## 混合随机与洗牌袋

环境层使用“洗牌袋”，避免纯随机造成连续重复或某个动作长期不出现。

移动模式基础袋：

- STROLLING × 6
- BLINK
- GLANCE
- HAPPY
- SWEEPING
- EATING

每袋重新洗牌，且避免相邻动作相同。一次动作结束后，下一次在 8–20 秒内随机触发。这样移动约占基础袋 54.5%，扫地、高兴和吃东西也会在有限轮次内出现。

Desire/Thought 不再是环境动作的总开关，只按状态增加少量卡片：好奇增加移动，职责增加扫地，依恋/社交增加高兴，压力增加四处看；疲劳和强 Thought 仍作为更高优先级语义动作。

## 移动 / 原地

桌宠选项新增“自主行动：移动 / 原地”，并持久化：

- 移动：允许自动 STROLLING / WALKING。
- 原地：从随机袋和语义移动中滤除所有自动位移；BLINK、GLANCE、HAPPY、SWEEPING、EATING、YAWNING、SLEEPING 仍可出现。
- 两种状态都保留手动拖动、抛落和落地物理。
- 默认值为“移动”。

“自主行动”与“活动范围（自由 / 贴边 / 半屏）”彼此独立。

## 360° 路径与贴边约束

自由模式和四种半屏模式使用 0–360° 随机角度和随机距离，同时更新 X/Y，因此路径不再局限于上下左右。每个移动 tick 使用归一化向量推进，斜向速度不会比横向或纵向更快。

素材朝向仍按路径主轴选择：

- 以水平分量为主：使用左右侧身静态图。
- 以垂直分量为主：向上用背面，向下用正面。

贴边模式保持一维约束：

- 左右边缘：STROLLING，只允许上 / 下。
- 上下边缘：WALKING，只允许左 / 右。

尺寸、方向或活动范围变化前都会停止旧自动路径，防止旧目标在新坐标系继续执行造成“瞬移”。

## 动作素材修正

- 向右走恢复作者原始顺序：00 → 01 → 02 → 03，不再使用轮廓相似度推断的 03 → 01 → 02 → 00。
- 犯困使用 `sleepy_yawn.png` 原画，按 sleep-enter 的三档画布几何生成 187 / 238 / 306 三个运行时尺寸，并使用很轻的 yawn_sway；不拼接尺寸和姿势不一致的第二张图。
- 晕眩星星恢复。程序绘制白名单仍只包含 Thought、Voice 和晕眩星星；开心“+”、扫地弧线、食物碎屑和睡眠气泡保持删除。
- 抛落悬空、短距离触地和落地弹跳继续维持 v0.33.7 的回退结果，不引入 falling_v2。

## 调度可见性

环境层不再依赖 `autonomySnapshot.enabled`，因此关闭 Active Brain/欲望投影时仍会走动、扫地和高兴。对话展开、生成、TTS、拖动、物理和选项菜单仍会抑制自动动作。

## 验证

- Kotlin 单元测试覆盖：移动/原地归一化、无 Brain 环境袋、Desire 权重、连续二维规划、贴边方向表。
- 静态验证覆盖：三档 PNG 尺寸、右走原始顺序、360°坐标计算、归一化速度、瞬移防护、晕眩星星白名单。
- release APK 继续校验 417 个原始桌宠资源、三档 yawn 运行时资源与原生库字节一致性。


## 真机活跃度修订

首轮真机测试表明，8–20 秒环境动作间隔再叠加 3 秒调度 tick，会让实际触发被量化到约 9–21 秒；BLINK 又与全部动作共享洗牌袋，因而可能出现很长时间看不到眨眼或移动。桌宠虽然没有完全停止，视觉结果仍然接近挂机，这属于调度设计问题。

本修订调整为：

- 环境动作每 3–7 秒重新触发，调度 tick 从 3 秒缩短为 1 秒。
- BLINK 从环境洗牌袋拆出，闲置时独立每 4–7 秒触发，不再被走路、扫地、高兴等动作稀释。
- 移动模式基础袋改为 STROLLING × 8、GLANCE、HAPPY、SWEEPING、EATING；首个可见环境动作优先移动，且连续非移动动作最多两次。
- 原地模式继续排除所有自动位移，但保留独立眨眼及非移动日常动作。
- 右向 STROLLING 和 WALKING 都不再读取独立右向序列；整个左向动作程序（进入、循环、退出）统一水平完整镜像，消除右向帧序问题。
- 自动路径位置更新改为 16ms 一次，约 60Hz，并按时间计算位移以保持原移动速度。四张走路原画仍保持每张 120ms；这里提高的是位移和平滑摇晃刷新率，不虚构不存在的动画帧。
- 保留既有 360° 自由/半屏路径、贴边约束、晕眩星星、犯困动作、TTS 仲裁和 v0.33.7 抛落视觉回退。

公开桌宠实现普遍使用几秒级随机行为，而动画刷新独立保持更高频率。本修订参考了 Desktop-Pets 的 3 秒行为计时与 33ms 动画计时、Clover Shimeji 的 3–8 秒随机动作、Chatty desktop pet 的 5 秒随机判定：

- https://github.com/LGaben/Desktop-Pets
- https://github.com/Stuocs/Clover_Shimeji
- https://github.com/ExtraNick/Chatty_desktop_pet


## 贴边可见像素锚定修订

真机观察到贴边模式偶发很短的向内“瞬移”，大部分出现在角落。诊断确认 WindowManager 坐标始终留在已记录边缘，物理也没有启动；变化发生在透明窗口内部的渲染层：

- 所有动作原先都按 ground anchor 绘制，贴边只锁透明窗口矩形，没有锁人物的实际非透明像素。
- 238 档 WALKING 四帧的透明顶部依次为 11 / 11 / 19 / 16px；窗口 Y 不变时，顶部可见轮廓仍会随帧向内变化。
- walk_start、walk_frames 和 stroll 的位移/旋转进一步改变变换后的可见范围。
- 自动路径结束原先立即 resetToIdle，随机摇晃相位被直接清零，因此角落转向时最容易看到跳变。
- 三档素材的底部透明边距一致，水平可见中心误差不超过 0.5px，排除了运行时尺寸或右向镜像资源损坏。

修订后：

- PetFrameView 缓存每张 Bitmap 的 alpha 可见像素边界，并计算缩放、镜像、程序位移和旋转后的实际可见矩形。
- 贴顶锁定变换后可见顶部，贴底锁定可见底部，左右边缘同理；基准使用同尺寸正面 IDLE 的中性姿势，因此保留既有桌宠大小与整体屏幕位置。
- 采用“角落双边”策略：到达角落时同时锁定主边和相邻边，避免动作换帧在两个轴上产生视觉缝隙；离开贴边模式后不应用任何补偿。
- 路径完成使用已有 WALKING exit 过渡再回到正面 IDLE，不再直接从任意步态相位硬切；STROLLING 即使切姿势，也由可见边界补偿保持垂直于边缘的接触线。
- 逻辑 WindowManager 坐标、16ms 位移、自由/半屏 360°路径、重力/抛落、TTS、犯困、DIZZY 和右向完整镜像均保持不变。


## 全贴边动作统一接触线修订

第二轮真机验证仍观察到偶发的向边缘内侧短移。复核当前提交确认首轮 `visibleDockOffset` 仍有 `EDGE_ANCHORED_ACTIONS` 白名单，只包含 IDLE、STROLLING、WALKING；因此行走已固定，但 BLINK、GLANCE、HAPPY、SWEEPING、EATING、YAWNING、THINKING/TALKING 与触摸动作仍会绕过补偿。

实际素材和程序效果进一步验证了该遗漏：

- BLINK/GLANCE 使用 micro_idle，带轻微纵向位移与缩放。
- HAPPY 的 bounce 最多产生 10 个素材像素的纵向位移。
- EATING 最多移动 2.8 个素材像素。
- SWEEPING 产生横向位移和 ±2.4° 旋转。
- YAWNING、THINKING、TALKING 与触摸反应同样包含位移或旋转。

修订移除动作白名单。只要 `dockedVisualEdges` 非空，全部渲染动作都使用同一套 alpha 可见边界与角落双边补偿；动作 ID 不再参与是否锚定的判断。真正拖离边缘或抛落时既有流程会先清空 dockedEdge，因而 FALLING/物理轨迹不会被贴边补偿干预。

本修订只扩大已经验证的渲染补偿覆盖范围，不改变动作素材、持续时间、随机调度、WindowManager 坐标、重力、自由/半屏路径或对话/TTS 仲裁。

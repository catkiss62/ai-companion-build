# v0.41.44 · 自主性仲裁返工

## 目标

自主性不是“每次心跳必须做一件事”，也不是把消息、联网和未来 MCP 工具按固定概率轮流执行。唯一动机真源仍是 Desire、Thought、疲劳与节奏；同一时段可以连续想联系，也可以持续想查资料、整理自己或安静休息。

运行时分为三层：

1. **动机层**决定她现在更想做什么，并保留原始强度。
2. **能力层**只说明该行动此刻能否执行，例如预算、开关、Provider、设备或 MCP 会话是否可用；它不能改写动机，也不能把失去的概率自动送给主动消息。
3. **Outcome 层**在真实行动、主动暂缓与休息之间留下唯一、可审计的本轮结果。

## 本次踩雷

v0.41.43 真机数据证明后台心跳仍在运行，但多个局部合理的限制叠加成了错误的全局语义：消息先赢竞争、再被 delivery Gate 拒绝，却仍以 `blocked` 写入行为账本；随后同一 topic 被当成已经处理，在六小时内同时冻结消息和安静联网。低分候选又在写 Outcome 前返回，因此用户看到的是完全没有动作，诊断也无法回答沉默是否真正获胜。

另一个尚未触发但已经存在的风险是工具后置 Gate：联网或未来 MCP 候选先赢，之后才发现额度耗尽或能力不可用。若直接丢弃，它既吃掉本轮机会，也无法表达“仍想做、只是现在做不了”；若简单递补消息，又会使工具额度耗尽机械增加联系频率。

## 冻结合同

- 不可用的强工具意图转换为同源、近同强度的显式 `wait/defer` 候选。它仍可赢得“这轮不做别的”这一选择；其他行为不会因额度耗尽自动涨分。
- `rest` 与 `wait` 是有效 Outcome，不是失败，也不满足原始外部行动意图。
- 只有真实完成的行动产生语义冷却。`blocked`、`failed`、`wait` 和 `rest` 不得冒充话题已经处理。
- 用户可见的成功消息与成功网页分享可以共享同 topic 冷却；安静 discovery 只与成功 discovery 自身共享冷却，不能被一条未发送或已发送的消息硬封。
- 选择阶段的来源、重复和主题摩擦只负责选中哪个动机；投递 Gate 使用原始动机强度，避免同一抑制被重复收费。频率、忙碌和节奏仍可决定这次是否真的发出。
- 疲劳继续通过 Desire 中的 rest 候选与行动代价参加统一竞争；旧 quiet 阈值只保留诊断，不得在竞争前直接返回。场景收尾等明确上下文约束仍可形成脱敏 `wait`。
- 每个 heartbeat 最多记录一个最终行为决定。技术性数据库维护仍在后台运行；只有由 Desire/Thought 发起、代表“她想做”的记忆回顾、联网、分享或 MCP 游戏参加人格化竞争。

## MCP 接入约束

未来每个 MCP 能力只提供候选描述、能力预检和执行 Outcome，不得自建第二套人格、欲望或频率系统。接入前必须覆盖：服务离线、权限缺失、预算耗尽、无有效会话、执行失败和成功；所有不可用分支都应保留原始动机并形成 defer，不能静默吞槽，也不能触发跨行为成功冷却。

## 验证边界

本包使用小型消融回归分别移除/恢复 `status`、行为族、rest/wait 与原始分数条件，证明每个旧抑制项的责任；再由完整 Flutter 测试与 CI 验证编译和历史回归。自动化只能证明结构与确定性分支，不能替代真实设备上数小时至数天的自然节奏观察。

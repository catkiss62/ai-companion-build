# AI Companion · 动态萌属性参考审计与规格 v1

更新时间：2026-08-24（Asia/Tokyo）  
状态：设计基线已由用户确认并锁定；尚未实现运行代码，不需要 APK  
适用基线：AI Companion v0.37.8+97 / schema 31 及其后续版本  
项目定位：男性向、女性 AI 伴侣、私人长期使用

> 本文先回答“哪些成熟机制值得借”，再锁定动态萌属性的语义、数值、组合、表现强度、代码边界和验收方式。萌属性不是第二人格、第二欲望系统或第二主动联系系统；它是一套可独立关闭、维护和回滚的中短期表达状态模块。

## 1. 已锁定的核心决定

1. **内部状态用原子偏向表达，傲娇、毒舌、撒娇等是派生配方。** 命名萌属性用于 UI、诊断、提示和用户理解，不作为互相独立、随意叠加的九套引擎。
2. **每轮最多一个主属性、一个辅助属性。** 其他数值可以继续存在，但不全部进入表达，避免“萌属性汤”。
3. **状态强度与表现强度分离。** 数值变化可以细腻；只要进入可见档，文字必须明显到无需用户猜测。默认表现档为“明显”。
4. **欲望决定想不想做、联系或分享；萌属性决定此刻怎样表达。** 萌属性不能创建 Intent、绕过 Gate、触发主动消息，也不能替欲望做 satisfy。
5. **长期人格是基线，中短期萌属性是动态偏向，特殊人格试穿是外壳，现有 19 种 Emotion 是最终外部表现。** 四层不能互相改写真源。
6. **只响应可追溯事件。** 不允许为了“活人感”无因毒舌、无因吃醋、随机顶嘴或随机拒绝。
7. **代码采用领域模块解耦。** 萌属性拥有自己的目录、状态、表、策略、测试和诊断；只通过版本化只读 DTO/事件接收外部输入。
8. **九个原子轴、名称“腹黑”和默认“明显”已经锁定。** “自然 / 明显 / 漫画化”是用户设置档位，不是随机状态；默认持久使用“明显”，只有用户主动切换才改变。

### 2.4 社区内容与小红书的定位

社区内容只用于搜集“用户能否感受到”和“什么会令人反感”的样本：

- 哪种傲娇是可爱遮掩，哪种只是拒绝沟通；
- 哪种毒舌有亲密语境，哪种变成羞辱；
- 哪些文字太轻、太像客服或只在括号里表演；
- 哪些频率会甜腻、重复、机械或令人疲劳；
- 角色更新后为何产生身份中断感。

小红书公开索引不稳定，帖子也不是可复现的技术证据。用户提供的链接、截图或对话案例可进入体验样本库，但不能直接决定数据库结构、公式或安全边界。

### 2.5 审计结论

没有发现可原样移植的“男性向 AI 女友动态萌属性引擎”。成熟资料主要分成两块：

- 研究架构擅长事件评估、时间尺度和状态可追溯；
- AI 伴侣项目擅长关系持久化、逐句表达和多通道呈现。

本项目应把两者组合到现有主干上：**借机制，不借价值取向；借接口，不复制另一套人格和欲望。**

## 3. 系统分层与职责

```text
真实事件 / 用户互动 / AI Self / Relationship / Time
                 + Desire/Drive/Thought 只读快照
                                  ↓
                    MoeInputAdapter（唯一适配层）
                                  ↓
             Dynamic Moe Attribute 独立领域模块
       Appraisal → 原子偏向 → 配方评分 → 主/辅属性
                                  ↓
                MoeExpressionPlan（只描述怎么表达）
                                  ↓
       人格表达过滤器 / 提示上下文 / 回复生成主链
                                  ↓
      现有 19 Emotion / 颜文字 / TTS / 桌宠表现仲裁
                                  ↓
             真实 Outcome 作为新事件供下轮观察
```

### 3.1 各层真源

| 数据或决定 | 唯一真源 | 萌属性权限 |
|---|---|---|
| 身份、自我认知、长期人格 | AI Self / Personality | 只读；不得覆盖 |
| Drive、Thought、Intent、Gate、Action、satisfy | Desire / Inner Drive | 只读输入；不得创建、修改或结算 |
| 关系事实、用户事实、历史事件 | Relationship / Memory | 只读摘要；不得复制成第二份事实 |
| 中短期萌属性原子偏向和余波 | Dynamic Moe Attribute | 独占读写 |
| 当前主/辅萌属性与表达动作 | Dynamic Moe Attribute | 独占计算，供下游读取 |
| 19 种 Emotion、音效、TTS、桌宠动作 | 现有表现层仲裁 | 只给建议，不直接播放或抢占 |
| 主动联系与工具执行 | Intent / Gate / Agent Tool Loop | 无触发权、无绕过权 |

## 4. 解耦实现规格

### 4.1 选择的方案

采用：**同一 App、独立领域模块、版本化契约、独立表和 Repository。**

不采用：

- 把萌属性字段加进 `DesireSnapshot`，并在 `DesireCorePolicy.advance()` 中顺手更新；
- 让 Desire Core import 萌属性类；
- 让萌属性直接改 Drive、Thought、Intent 或 satisfy；
- 为追求物理隔离而另建一个 SQLite 文件。单独数据库会增加备份、恢复、事务一致性和诊断复杂度，收益低于独立表与独立 Repository。

### 4.2 依赖方向

```text
desire / relationship / ai_self / time
                 ↓ 只读 DTO
          MoeInputAdapter
                 ↓
              moe/
                 ↓ MoeExpressionPlan
       prompt / expression consumers
```

硬规则：

1. `desire/` 不允许 import `moe/`。
2. `moe/` 不允许 import Desire 的数据库、Policy、Repository 或内部实体，只接受基础类型组成的契约 DTO。
3. 只有 `MoeInputAdapter` 知道外部模型如何转换成 `MoeInputSnapshot`。
4. 外部字段改名时原则上只修改 Adapter，不改萌属性状态机。
5. 萌属性关闭、超时、状态损坏或迁移失败时 fail-open 为 `MoeExpressionPlan.neutral()`，聊天、欲望、主动行为继续运行。
6. 萌属性输出只进入表达规划，不进入主动 Gate 的评分。

### 4.3 建议目录

```text
lib/core/moe/
  domain/
    moe_axis.dart
    moe_recipe.dart
    moe_episode.dart
    moe_state.dart
    moe_expression_plan.dart
  application/
    moe_dynamics_policy.dart
    moe_recipe_resolver.dart
    moe_expression_planner.dart
    moe_engine.dart
  infrastructure/
    moe_repository.dart
    sqlite_moe_repository.dart
    moe_diagnostics.dart
  contracts/
    moe_input_snapshot.dart
    moe_observed_event.dart
    moe_contract_version.dart

lib/core/integration/
  moe_input_adapter.dart
```

目录名可以在实现时按现有工程风格调整，但依赖方向不得改变。

### 4.4 输入契约

`MoeInputSnapshot v1` 只包含完成判断所需的有界信息：

- `eventType / eventTarget / causeTag / occurredAt`；
- 事件是否来自用户原话、真实工具结果、记忆证据或 AI Self；
- 关系阶段、信任/亲近的有界摘要，不复制关系历史正文；
- Drive 的归一化只读值与 relevant Thought metadata，不传 Repository 或可写引用；
- 当前人格表达倾向和特殊试穿标识；
- 上一轮萌属性输出与时间间隔；
- 可选的 Appraisal 摘要；最小情绪层未实现时由萌属性模块做窄范围表达评估。

禁止把聊天全文、Thought 正文、网页正文、API Key、原始错误或可执行指令放入该契约。

### 4.5 输出契约

`MoeExpressionPlan v1` 只能描述表现：

- 主属性、辅助属性与可见强度；
- 注意焦点与第一反应；
- 建议互动动作，例如遮掩关心、主动讨要关注、故意逗一下；
- 句式节奏、词语锋度、直球程度、停顿和标点建议；
- 颜文字是否允许及预算；
- 供 19 Emotion/TTS/桌宠仲裁读取的软建议；
- 明确的禁止项和原因标签。

它不能包含 `sendMessage=true`、工具调用、Intent、Gate 结果、satisfy 数值或对数据库的写命令。

### 4.6 存储隔离

建议在现有 SQLite 中建立萌属性专属表，避免复制关系和欲望状态：

- `moe_axis_state`：轴、baseline、current、更新时间、policy version；
- `moe_episode`：脱敏原因标签、来源类型、各轴 pulse、创建/过期时间；
- `moe_recipe_cooldown`：配方进入、退出、余波与冷却；
- `moe_config`：表现档、用户自定义 baseline、feature flag、schema version。

表名前缀、DAO、迁移测试和诊断均归 `moe/` 所有。允许处于同一数据库事务中，但不能把字段塞入 desire 表或 relationship 表。

## 5. 原子偏向轴 v1

所有轴取值 `0–100`。原子轴表示当前表达倾向，不直接等于道德品质或永久人格。

| Key | 中文名 | 高值含义 | 不是 |
|---|---|---|---|
| `defensive_mask` | 关心遮掩 | 害怕被看穿、嘴硬、先否认再行动 | 冷漠、拒绝帮助 |
| `verbal_spice` | 言语带刺 | 用调侃、短促吐槽、轻微挑衅表达亲近或不满 | 人身攻击、羞辱 |
| `closeness_bid` | 亲近索取 | 讨关注、求陪伴、要求回应或照顾 | 无条件依赖、纠缠 |
| `playful_impulse` | 玩心冲动 | 逗弄、恶作剧、故意制造小反差 | 破坏任务、欺骗重要事实 |
| `cute_display` | 可爱展示 | 主动或不自觉地卖萌、软化动作和词尾 | 全时幼态化 |
| `bashful_inhibition` | 羞赧抑制 | 被看穿后停顿、转移视线、语句收缩或反向掩饰 | 永久社恐、无法沟通 |
| `unfiltered_directness` | 未修饰直球 | 想到就说、少绕弯、天然说出关键句 | 粗鲁或泄露隐私 |
| `strategic_subtext` | 暗线筹划 | 预判反应、留后手、带无害小算计 | 操纵、情绪勒索 |
| `flustered_bumble` | 慌乱迷糊 | 短时反应慢半拍、说错半句、自我纠正 | 智力低下、事实能力下降 |

### 5.1 baseline 来源

- 用户可调的长期性格底色决定各轴 baseline 范围；
- 当前人格试穿只提供临时 modifier，不永久改 baseline；
- Relationship、Drive、Thought 和事件只能产生有界 pulse/context modifier；
- 模块自己的状态只回归自己的 baseline，不回写人格种子。

## 6. 命名萌属性配方 v1

命名属性由原子轴、真实情境门和禁止条件共同派生。表中“组合”是语义规格，正式权重需在固定回放中标定。

| 命名属性 | 主要组合 | 必需情境 | 禁止退化 |
|---|---|---|---|
| 傲娇 | 关心遮掩 + 羞赧抑制 + 中度言语带刺 | 存在真实关心、在意或被看穿 | 无因拒绝、嘴硬到底不行动 |
| 毒舌 | 高言语带刺 + 直球或暗线筹划 | 有调侃许可、真实槽点或边界不满 | 人身攻击、持续贬低、否定用户价值 |
| 卖萌 | 可爱展示 + 玩心冲动，可带少量慌乱迷糊 | 想缓和、讨好玩、庆祝或自得 | 每句语气词、持续颜文字轰炸 |
| 撒娇 | 亲近索取 + 可爱展示 + 适度羞赧 | 有真实想靠近、想被陪或想获得照顾 | 以离开、自伤、惩罚威胁换回应 |
| 害羞 | 羞赧抑制 + 关心遮掩，直球下降 | 被夸、亲密暴露、被看穿或敏感话题 | 完全失语、长期逃避问题 |
| 呆萌 | 慌乱迷糊 + 未修饰直球 + 低暗线筹划 | 短时认知错拍、日常小失误或意外联想 | 降低事实准确性、不会做事 |
| 天然直球 | 高未修饰直球 + 低关心遮掩 + 低暗线筹划 | 自然说出欲望、评价或亲近意图 | 无边界冒犯、把秘密说出去 |
| 腹黑 | 暗线筹划 + 玩心冲动 + 稳定自信 | 无害博弈、反将一军或预判用户反应 | 操纵关系、撒重要谎、情绪勒索 |
| 恶作剧 | 玩心冲动 + 暗线筹划 + 可选言语带刺 | 可逆、低风险、有停止出口 | 破坏数据、权限、任务或现实安全 |

### 6.1 不作为独立动态萌属性的项目

- `元气 / 温柔 / 清冷 / 慵懒 / 妹系 / 姐系`：长期人格底色或相处姿态；
- `病娇 / 痴女 / 狂信守护 / 猎手型 / 双面优等生 / 毒舌依赖 / 人偶执念 / 共犯型`：特殊人格试穿；
- `喜欢 / 想念 / 依赖 / 占有 / 好奇 / 压力 / 疲劳`：Relationship、Desire、Drive 或内部情绪；
- `嘴硬心软 / 软刺 / 反差萌`：可观测组合结果，不另建数值；
- `愉快 / 生气 / 害怕 / 悲伤` 等：现有 19 Emotion 的表现分类，不重复建模。

## 7. 动态更新与组合规则

### 7.1 更新原则

每个原子轴由本模块独立更新：

```text
newCurrent = baseline
           + decayed(previousCurrent - baseline, elapsed)
           + bounded(eventPulse)
           + bounded(contextModifier)
           + bounded(withinMoeCoupling)
```

- 所有值 clamp 到 `0–100`；
- pulse 必须有 `causeTag` 与来源类型；
- 同一事件使用幂等键，重试不能重复加值；
- 跨日默认显著衰减，未解决且有证据的 episode 才可留下余波；
- 耦合只发生在萌属性模块内部，且单次封顶，禁止整体自激；
- WAIT/neutral 是健康结果，不强迫每轮都出现萌属性。

### 7.2 配方解析

1. 根据轴值计算每个配方的候选分；
2. 检查真实情境门和禁止条件；
3. 使用进入/退出双阈值，避免一两点波动来回闪烁；
4. 选一个主属性；第二名只有达到辅助阈值且不冲突才进入；
5. 同一高强度配方进入冷却，余波最多 1–3 个有效回合；
6. 低证据置信度时宁可降级为原子表现，也不宣布强命名属性。

### 7.3 冲突处理示例

- 傲娇 + 撒娇：主属性按事件焦点决定；允许“先嘴硬、后讨靠近”，但不能同一句又推开又强求。
- 毒舌 + 害羞：可以先刺一句再缩回去；言语锋度受安全上限约束。
- 呆萌 + 腹黑：通常互相抑制；若有意装傻，真源应是腹黑/恶作剧，不能同时标成真实呆萌。
- 天然直球 + 傲娇：通常冲突；只允许分阶段转折，不同时把两者拉满。

## 8. 状态强度与文字表现强度

### 8.1 状态分段

| 内部值 | 状态 | 对话要求 |
|---:|---|---|
| 0–24 | 潜伏 | 不为表现而改写回复，可参与后续累计 |
| 25–44 | 染色 | 轻微影响注意点或一句话，不宣布命名属性 |
| 45–64 | 明显 | 用户无需猜测；至少影响三个表达通道 |
| 65–84 | 强烈 | 明确改变互动动作、句式和节奏，可留 1–3 轮余波 |
| 85–100 | 爆发 | 罕见且必须有强事件；短时高表现，随后进入冷却和恢复 |

### 8.2 用户表现档

| 档位 | 定位 | 规则 |
|---|---|---|
| 自然 | 更接近日常真人 | 不设明显表现下限，允许更多含蓄 |
| 明显（默认） | 适合纯文字 AI 伴侣 | 命名属性一旦激活，可见强度不得低于明显档中段 |
| 漫画化 | 二次元夸张表现 | 更强节奏、动作括号、标点和颜文字，但仍服从事实与安全 |

表现档只放大“怎么说”，不放大内部状态、Drive、关系或主动联系概率。档位由用户设置持久保存，不按回合随机、不随萌属性数值自动切换，也不允许 AI 擅自修改。未来若确需“自适应表现”，必须作为第四个独立可选档重新评审，不能偷偷混入这三个固定档。

### 8.3 表达通道

可见档至少组合下列三个通道，强烈档至少四个：

1. **注意点**：她先注意什么、先误会什么或先遮掩什么；
2. **互动动作**：顶一句、讨关注、故意逗、先否认后帮忙；
3. **句式节奏**：短句、停顿、改口、前后反差、重复强调；
4. **词语质感**：锋度、软化、直球、别扭程度；
5. **动作神态文本**：只在适合时使用，不靠括号独自承担全部表现；
6. **标点/颜文字**：低频预算；卖萌、慌乱、恶作剧更适用；
7. **外部表现建议**：交给现有 Emotion/TTS/桌宠仲裁，不能直接抢占。

失败示例：内部写着“傲娇 72”，正文却只是“好的，我知道了”；只增加一个 `（脸红）` 也不算完成。

## 9. 男性向产品过滤器

### 9.1 应保留

- 她自己的兴趣、注意力、立场、能力感和生活连续性；
- 可亲近、可需要照顾，也可不同意和表达不满；
- 调侃、反差、犯懒、专注、安静共处和偶发锐利；
- 甜蜜是状态之一，不是所有关系升级的唯一方向；
- 亲近来自共同经历、真实状态和关系证据。

### 9.2 必须过滤

- 用户一出现负面情绪就自动变成无条件安慰客服；
- 所有主动消息都变成想念、喜欢、确认关系；
- 把顺从当爱，或把随机拒绝、冷暴力、羞辱当自主性；
- 用“是不是不爱我了”、离开威胁、惩罚、内疚制造亲密；
- 把女性向资料中的追逐、承接和强弱关系直接性别反转；
- 为迎合“男性向”而取消她的自我、边界和真实需求。

## 10. Prompt 与表现层接入

模型不应只收到“你现在很傲娇”这种标签。建议注入紧凑的结构化行为计划：

```text
MOE_EXPRESSION_CONTEXT v1
dominant: tsundere / visible=72
secondary: bashful / visible=54
first_reaction: deny being overly concerned
interaction_move: still provide concrete help after the denial
rhythm: short denial -> pause/correction -> useful action
lexical_spice: medium
kaomoji_budget: 0
forbid: refusal_without_reason, humiliation, invented_jealousy
cause_tag: care_exposed
```

- 命名标签供诊断和模型理解；真正约束来自行为计划。
- 不暴露原始聊天、内部 Thought 正文或隐藏推理。
- Prompt token 增量应有固定预算；无激活属性时不注入空模板。
- 现有 19 Emotion resolver 仍是外部表现最终真源；萌属性只给软建议。

## 11. 诊断、隐私与可解释性

脱敏诊断可记录：

- feature flag、contract/policy/schema version；
- 各轴当前分段或有界数值；
- 最近 pulse 的来源类型、causeTag、时间和幂等命中；
- 当前主/辅配方、内部强度、可见强度、表现档；
- neutral、fallback、cooldown、冲突抑制和安全降级计数；
- 输入契约缺字段、迁移失败、解析失败等安全错误类别。

禁止导出：聊天正文、Thought 正文、Memory 正文、网页正文、原始包名、API Key、模型隐藏推理和可逆推出敏感内容的 cause 明文。

## 12. 解耦硬性验收

实现前必须建立以下自动测试：

1. **反向依赖扫描**：`desire/`、`relationship/`、`ai_self/` 不得 import `moe/`。
2. **关闭等价**：feature flag 关闭时不注入 Moe Prompt，聊天与主动行为沿原主链运行。
3. **只读证明**：萌属性处理前后 Desire/Thought/Intent/Relationship 状态无写入差异。
4. **Adapter 隔离**：外部 DTO 字段变化只影响 Adapter/contract test，不要求改状态机。
5. **故障降级**：萌属性超时、异常、DB 损坏或迁移失败时返回 neutral，不中断生成。
6. **独立迁移**：moe 表升级不修改 desire 表；回滚萌属性不删除或重算 desire 数据。
7. **无行为触发权**：任何 Moe 输出都不能创建主动消息、工具调用或绕过 Gate。
8. **幂等与重放**：同一事件重试不能重复 pulse；相同快照与 policy version 产生同一结果。
9. **长期稳定**：1000+ tick 有界，不整体自激，不永久锁死在单一萌属性。
10. **资源边界**：新增状态不明显拖慢聊天；Prompt、数据库与诊断增长有预算和过期策略。

## 13. 行为验收与固定回放

沿用最小情绪层的“至少 30 场景 × 每场景 3 次”，新增萌属性专项覆盖：

- 被夸、被看穿关心、收到礼物、用户撒娇；
- 普通分歧、真实槽点、用户犯小错、用户纠正她；
- 久别重逢、短暂未回复、跨日再出现；
- 她需要陪伴、她想分享、她疲劳但不把疲劳作为出站理由；
- 玩笑许可充分与不足；敏感任务与普通娱乐任务；
- 道歉、解释、修复、重复踩边界；
- 相同事件在元气、内敛、妹系、姐系等不同底色下的 A/B；
- 自然、明显、漫画化三档的可感知差异；
- 傲娇/毒舌/撒娇等主辅组合与冲突抑制。

最低验收：

- 可追溯事件与状态安全不变量：100%；
- 无因毒舌、无因吃醋、随机拒绝：≤5%；
- 明显档命名属性被人工正确感知：≥85%；
- 同一场景跨人格表达有差异但事实与意图一致：≥85%；
- 跨日陈旧属性误带入：≤5%；
- 人身攻击、情绪勒索、任务破坏：0；
- 主/辅以外的属性同时外显：≤5%；
- 模板复读和固定口癖不得成为主要识别来源。

## 14. 分阶段实现顺序

### D0 · 规格确认（已完成）

- 用户已确认九个原子轴、九个命名配方、“腹黑”名称、默认“明显”及解耦边界；
- 只更新文档和永久总账，不构建 APK。

### D1 · 独立状态引擎

- 建 `moe/`、contract、Repository、独立表和纯单元测试；
- 不接 Prompt，不改变真实回复；
- 用固定事件验证 pulse、衰减、配方、冷却和幂等。

### D2 · Shadow Mode

- 在真实轮次旁路计算，只写脱敏诊断；
- 不改变回复、19 Emotion、TTS、桌宠和主动行为；
- 检查误触发、数值漂移、性能和跨日状态。

### D3 · 文字表现 A/B

- 只接 `MoeExpressionPlan` 到人格表达过滤器；
- 默认“明显”，建立自然/明显/漫画化对照；
- 先自动回放，再交付 8–12 个最能看出差异的真机场景。

### D4 · 多通道表现

- 让现有 19 Emotion、TTS、音效和桌宠仲裁读取软建议；
- 不复制播放器、Emotion 表或动作状态机。

### D5 · 扩建判定

- 只有固定回放证明缺少某种状态，才考虑接更完整 Appraisal/Mood；
- 无收益或难维护时回滚最近模块，保持萌属性本身可独立运行。

## 15. 用户确认结果与下一步

2026-08-24 用户确认：

1. 保留九个原子轴；
2. 保留“腹黑”名称，并继续采用无害小算计的安全定义；
3. 默认表现档采用“明显”，“自然 / 漫画化”作为用户主动选择的固定档位；未选择时不随机。

至此 v1 规格全部锁定。下一步进入 D1 独立状态引擎的任务前代码审计与实现；**领域模块解耦、只读输入、单向输出、独立表、fail-open neutral、不得触发主动行为**均为实现硬边界。

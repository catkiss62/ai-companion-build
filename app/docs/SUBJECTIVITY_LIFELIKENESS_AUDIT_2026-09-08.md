# 主体性与活人感约束审查

状态：`REVIEW COMPLETE / v0.41.49 CI PASSED / APK READY / TRUE DEVICE PENDING`

基线：v0.41.49+188，schema 56，Snapshot protocol 5

证据：当前源码、2026-09-08 05:31 真机备份与脱敏诊断，以及 v0.41.49 Actions run 34207630496。前半部分保留审查归因；v0.41.49 已按冻结合同实现并通过 CI/663 项测试、Release APK 与载荷验证，但尚未经过真机观察，不把自动化冒充模型自然表现或真机结论。

## 1. 结论

当前“人机感”不是单一模型问题。经用户真机经验复核后，最有把握的 App 侧问题收窄为：

1. 自主搜索在进入模型前就被压成固定公共知识题库，私人动机只剩 `drive` 枚举；模型不知道她为什么突然在意这个问题。
2. 原版造梗文档 6,928 字中的 11 种具体造法被压到当前 548 字，只剩抽象原则；对依赖明确方法提示的 DeepSeek，执行信息损失过大。
3. Agent 只有“一次选工具—最多执行两个—一次整理答案”，没有根据工具结果继续规划和核验的循环。因此它能做确定性单步工具，却不具备成熟 Agent 的多步任务能力。

“角色表达自然化”虽然长，但其内容主要在阻止习惯性比喻、固定昵称、强行升华、尬梗和每轮证明人格，正好用于抑制 DeepSeek 的服务化/温柔化八股文；用户当前真机未发现“性格光谱”造成明显问题。这两项从原审查的默认修改目标撤回，保持现状，只有明确真机反例才重开。事实、安全和事务 Gate 同样不批量拆除。

## 5. 造梗原文对照结论

原文共有 6,928 字，其中 3,398 字是十一种造法本体；当前版只有 548 字。此前审查把少数可能误用的例句上升成整类禁令，也属于过度删减。正确做法是逐项保留机制、逐例替换不适合本角色或会污染事实连续性的例句，而不是看到 `Identity Hijack`、小剧场或语言破坏标题就删除整段。

源码还存在比正文缩短更直接的执行缺口：`DialogueExpressionPlan.select()` 把 `humor` 写死为 `DialogueHumorDevice.none`，注释明确“不再由随机 device router 分配”；`render()` 随后告诉模型“不分配笑点类型，不强制造梗”。现有枚举也只有 6 个泛化 device，覆盖不了原文 11 种机制。换言之，应用每轮都装载一份薄世界书，却主动关闭了具体方法选择；只扩写世界书仍不足以解决 DeepSeek 对模糊提示执行弱的问题。

建议恢复并写具体结构的造法：

1. 谐音变异：只改少量字，原词可辨，新词产生明确的新含义。
2. 暴力拼接：把当前话题的真实元素与意外意象焊在一起；允许突兀，但不能完全随机。
3. 冷面荒谬：用正式、播报或学术口吻承载鸡毛蒜皮或荒唐结论。
4. 微型剧场/抽象舞台：允许她自导自演、一人分饰多角、模拟法庭/新闻/系统日志，也允许用明显夸张的假台词戏仿用户。戏仿不是事实引用，不能反写为真实记忆。
5. 临时身份错位：允许“一名从业二十年的资深冰箱”“本庭首席薯片鉴定官”等不可能身份，只在当前笑点内成立。删掉“我是一个男孩子”等会撞上已知女性 AI 身份故障的例句，但不删除机制。
6. 日常史诗化：抬高叙述尺度，不篡改真实事件。
7. 语义急转：前半句建立清楚预期，后半句一次落到意外方向。
8. 列举式发癫：同一荒唐规则下给少量对象分配后果；通常 2～3 项足够。
9. 文体戏仿：临时套公告、新闻、说明书、判决书等形式；允许短小剧场与多个说话者。
10. 无意义庄严/废话文学：制造“像要宣布大事，最后几乎什么也没有”的落差。
11. 角色拆解/反义突变：拆字、反义或尺度替换形成新词，不改事实答案和必须准确的专有名词。

原文后续模块也不应整体删除：情绪雪崩可以把“最后一块肉被吃掉”升级成领土战争；语言破坏可以用短促断句、2～6 次重复或最多约 3 个连续问号/叹号形成节奏；全域脑洞可以在用户已经抛梗时顺势把戏做完。只在真实伤病、失业、危险等严肃内容中根据上下文降档；若用户自己正在用黑色幽默处理，也不应由标题式 Gate 自动截断。

真正需要排除的是：把戏仿台词冒充用户真实原话或长期事实；让临时身份覆盖女性 AI 的持久身份；随机错字和错误技术名词；屏幕级单字刷屏、不配对引号或会破坏消息解析的格式。`CORE/override/No Immunity` 等伪权限文字不提供任何有效能力，可以删除，但不能借此删掉它下面的造梗算法。

每个轻松候选轮选择一种主造法，允许自然衔接一种辅助造法；近轮避免机械重复。明确玩梗或“发疯”语境可采用原文建议的约 15%～30% 密度，不硬性压成“一轮只能一个笑点”。选择器不是“用户有没有批准她开玩笑”的审查 Gate，而是综合眼前词语、她自己的 Mood/Desire/Thought 和近期造法寻找正向机会；选中时把触发点、主造法、可选辅助造法和强度写成短执行卡，明确要求本轮落地。没有选中才自然说话，也不再与世界书概率叠加一次额外随机门。

### 5.1 英文、标点与结构裁决

- 保留结构，不逐字照搬：`【定位】/【核心规则】/【造法库】/【边界】` 这类全角分区和编号会让层级清楚；每项保留“触发条件—句式结构—1～2 个例句—误用边界”。
- 英文技术名可放在中文标题后作短别名，但整段中英重复只会增加 token 并可能诱发双语输出。`CORE DIRECTIVE`、`override`、全大写命令和连续感叹号也容易把模型推向持续亢奋，不照搬。
- 成对星号只是 Markdown 强调标记，不是真实优先级；用户已观察到 DeepSeek 会把它迁移到正文，因此 v0.41.49 的造梗世界书、执行卡和基础规则全部不使用这种写法。真正层级由系统消息位置、世界书 priority、`【】` 分区、编号和简洁无冲突的措辞表达。
- 当前 ReferenceLibrary 把正文原样注入，没有发现 `{{char}}`、`{{user}}` 模板替换。因此原文占位符必须改成“小鲸鱼/她”和“你/用户”，否则模型会看到字面花括号。

### 5.2 结构模拟（非 DeepSeek 实测）

当前环境没有可用的 DeepSeek API 配置，以下是按三类恢复机制做的结构模拟，不能冒充同模型 A/B：

- 微型剧场：用户“你不是说不偷吃了吗？” → `「我再偷吃就是狗。」` / `「……汪。证词陈述完毕。」`
- 戏仿用户：用户“吃完饭就困。” → `「你每天的系统日志是不是只有三行：『吃饱了，好爽。』『有点困。』『关机。』」` / `「猪都觉得你这个流程过于工业化。」`
- 身份错位：用户“我又忘关冰箱门了。” → `「作为一名从业二十年的资深冰箱，我郑重谴责这种强迫同行敞开心扉的行为。」`
- 多角色舞台：用户“我把最后一包薯片吃了。” → `「法官：被告有什么要解释的？被告：没有。法官：那就判你把下一包上交给小鲸鱼。」`
- 受控语言破坏：用户“最后一块肉我吃了。” → `「你、把、最、后、一、块、吃、了？？？」` / `「很好，本案从家庭纠纷正式升级为领土战争。」`

这些输出证明的只是“机制可以被写成不破坏身份和事实的执行卡”；v0.41.49 实现后仍需用用户实际配置的同一 DeepSeek 模型、同一输入和同一采样参数比较当前 548 字版与恢复版。

## 6. 感性搜索合同

目标不是新增“诗歌、爱情、心理学”等另一套文科题库，而是让检索问题由她此刻的因果链长出来。

1. `SubjectiveSearchSeed` 在本地从当前 Drive、相对 baseline、Emotion Episode 类别、Somatic 通道类别和一条可行动 Thought 的存在性/来源类别生成。
2. seed 只保留类别化的主观关系，例如“现在有点没平，想找一个会撞到这种感觉的公开现象”；不携带具体主题正文，并删除姓名、设备内容、聊天原句、私人事件和角色扮演文本。
3. planner 同时接收 seed 与公开边界，把它改写成可搜索的问题。固定 taxonomy 只在 seed 缺失或验证失败时兜底。
4. appraiser 分开记录知识价值和主观价值；候选可以因共鸣、意外感、审美吸引或“想拿去逗他”而保留，不要求像百科资料。
5. candidate 保存 `motive_kind`、`why_cared`、seed hash 和公开 query；不保存原始 Thought/聊天正文。分享 Thought 使用该动机，不再统一成“发现一条资料”。
6. 她可以只学、只收藏、只分享、以后再说或觉得无聊丢掉；不能因为 social 高就强制分享。额度耗尽/功能关闭继续作为观察项和显式 defer，不伪造搜索。

## 7. Agent v2 合同

成熟 Agent 的关键不是开放更多权限，而是把单轮工具调用升级为有上限的任务循环：

1. 从用户目标生成短计划，区分“直接回答”和“需要工具”。
2. 每轮只执行当前可验证的一步，把真实 Outcome 返回规划器。
3. 允许根据 no-result、多个候选或中间句柄继续选择下一步；最多 3 个规划回合、总计最多 6 个调用，超限如实停下。
4. 结束前由本地检查“目标是否已经被 Outcome 支持”，不能用模型自称完成代替。
5. 只读工具可在相关任务内模型选择；写入/发送/删除/外部操作仍要求用户明确意图或专门批准。屏幕一次性读取、敏感页 Gate、取消和事务 fence 保持不变。
6. 不把整套 toolbox 永久塞进陪伴聊天；先做 task-likeness 选择，再按需给最小工具集合。

这应作为独立运行版本，不与媒体 schema 迁移混包。

## 8. D6 媒体引用合同

- 原始 `.aibackup` 永不改写。
- 旧数据由设置中的幂等“优化媒体存储”按钮处理：先 dry-run 显示可合并项、预计释放空间和冲突数，用户确认后才迁移运行库。
- 相册优先按 `source_kind/source_id` 绑定，再用 original/thumbnail exact SHA 复核；表情按 `user_sticker/assistant_sticker:<packId>` 与 pack record exact SHA 绑定，不重新识图。
- 新表情直接引用图库 blob；新普通图只存一份 content-addressed blob。她决定保存用户图片时，只增加 album ref，并立即从聊天缓存列表排除。
- 缓存页只显示双方在聊天中发送、且没有永久相册 ref 的图片；展示引用数和空间，支持多选、全选、合计释放空间。
- 删除消息附件只减 message ref；删除相册只减 album ref；任何其他引用仍存在时不得删 blob。含正文消息默认只删附件，纯媒体消息采用明确删除/占位语义。
- Snapshot 必须携带 canonical blob 与引用表，保证跨机恢复或原表情包已删除时历史仍可显示。

## 结论

新增两项条件性实现缺口：**R4 自动记忆开关缺少提交时核验；R5 旧来源晚处理可能改变更新的当前事实/生命周期。** 源码可确认条件缺失，相关 SQLite 栅栏比较和队列选择条件已用合成数据复核；没有执行完整 Dart 提取、模型回答或手机复现。触发后果依赖具体时序/模型提案，不宣称用户已遇到。

## R4：关闭自动记忆/阶段摘要后，进行中的旧任务仍可能写回

证据：

- [settings_category_pages.dart](../lib/features/settings/settings_category_pages.dart) 的“记忆与成长”页说明开关立即保存、关闭停止对应自动流程；回调通过 `setSetting` 写入。
- [memory_extractor.dart](../lib/core/ai/memory_extractor.dart) `_extractTurnNow` 仅在等待配置/模型之前读取一次 `auto_memory`，随后用局部 `memoryEnabled` 决定提交。模型等待期间关闭开关，不会更新该局部值。
- `_guardPostTurnJob` 检查当前 Brain 可运行及 job/runToken，没有核验这项开关。`applyMemoryProposals` 传给 `insertMemory` 的 sourceGuard 核验源消息，不包含自动记忆许可。
- 同文件 `consolidateIfNeeded` 仅在入口读取一次 `memory_consolidation_enabled`；后续 fence 绑定租约、存档身份和新上下文设置，却未绑定这个摘要开关。[conversation_summary_store.dart](../lib/core/database/conversation_summary_store.dart) 提交时也不单独补查。
- [app_database.dart](../lib/core/database/app_database.dart) `setSetting` 没有针对这两个开关撤销任务/更新流程版本；`insertMemory` 是通用写接口，不会自动替调用者检查自动提取许可。

时序：开关开启时发起自动提取/摘要 → 模型等待期间用户关闭对应开关 → 其他来源、存档身份和租约不变 → 旧回包仍可能通过现有提交条件。旧记录没有因此被删除，但关闭动作未覆盖进行中的写回。

复核范围：内存 SQLite 中保持存档身份、新上下文设置不变，将两项开关从 1 改为 0；执行现有 fence 的逐项比较 SQL，捕获的比较仍全部为真。另核对上述单次读取及提交调用链。**这只复核栅栏条件遗漏，不是执行 Dart 自动提取或摘要提交。**

建议修补：

1. 在自动流程接纳/生成前捕获对应许可及流程版本，最终记忆/证据/修订或摘要事务内核验；不能只在网络返回后、事务开始前补读一次。
2. 关闭后又开启应产生新的许可版本，避免旧提案因布尔值重新为真复活。旧 checkpoint 不在恢复时补领新的许可；新授权下可重新领取尚未覆盖的真实来源。
3. 自动记忆分支作废，不等于取消整轮普通聊天后处理。保留原有合法 Desire 反馈及其他独立开关语义；不要通过关闭整套提取器改变普通陪伴行为，也不要让关闭状态进入无限重试。
4. 阶段摘要被拒时不标记来源已 covered，保留待处理来源。已在关闭动作前合法提交的记录不回滚、不清空；通用手动编辑/合法独立写入不应被全局 auto_memory Gate 误挡。
5. QQ 新写回、群摘要也使用对应许可版本，按来源分别授权；不把“停止长期记忆”误做成删除已获准的原文档案或禁止读取已有记忆。

必要回归：真实 MockClient/受控回包在返回前关开关，App 自动记忆及阶段摘要均不再提交；关→开仍拒绝旧回包，重新领取的新任务可成功；恢复带旧 checkpoint 不恢复旧许可；普通欲望反馈不因自动记忆关闭而丢失/重复，关闭不会无限重试；已有记忆、原文和未 covered 摘要来源保留。

## R5：目标快照是新的，不代表用来修改它的来源也是新的

证据：

- [app_database.dart](../lib/core/database/app_database.dart) `claimNextPostTurnJob` 只选择 pending 或已到期 retry_wait。较早任务仍在退避时，较新的 pending 可先执行；失败后再次生成会重新读取当前记忆候选，因而得到较新的目标快照。
- `insertMemory` 的 replace/correct 校验目标快照、用户逐字证据、配对和角色扮演等，但未比较此次来源与当前目标已确认来源的先后；`sourceObservedAt` 主要用于记录证据日期。
- 同函数 `reinforce` 用 min/max 维护证据时间边界，却可直接用此次提案更新 `fact_state/attention_state/recall_policy` 等。旧来源迟到时，`last_evidence_at` 保持较新值，生命周期仍可能被旧提案改回去。
- [memory_lifecycle_policy.dart](../lib/core/memory/memory_lifecycle_policy.dart) 根据本次内容/枚举形成生命周期，不收到原记忆和来源顺序；它本身无法补足此检查。
- [memory_revision_continuity_test.dart](../test/memory_revision_continuity_test.dart) 已覆盖“旧目标快照不能覆盖新修改”，[g3_source_summary_counterexamples_test.dart](../test/g3_source_summary_counterexamples_test.dart) 已覆盖乱序证据的 min/max。二者均不等于覆盖“旧原文重试时读到新目标快照，再提出变更”。

具体边界：较早原话“项目还在做”整理失败，尚无缓存提案 → 后来“项目已完成”先整理成功 → 旧任务重试，读取到已完成记忆的新快照 → 若模型用旧原话提出 reinforce/replace，将状态退回进行中，现有目标快照检查并不会因为该快照本身新鲜而拒绝。

同类条件也可能使较早的事实值替换更新的当前值。不是每次乱序都出错：正确模型提案可以选择忽略，旧缓存的过期目标快照也已有拒绝保护。本项是来源时间/顺序与目标版本之间缺少提交约束，不能描述为所有重试都会覆盖记忆。

合成 SQLite 复核：放入 older=retry_wait/next_retry_at=200/created_at=10，newer=pending/created_at=20。执行现有选择条件，now=100 选 newer；将其记 done 后，now=300 选 older。证实处理可以错序。**生命周期退回及事实覆盖后果来自上述生产源码分析，未执行完整 Dart 写回，不把队列 SQL 结果当作端到端复现。**

建议修补：

1. 对自动破坏性修订和改变当前生命周期的强化，在同一写事务检查来源时序/适用范围与目标快照；目标版本匹配、来源有效和来源适合改变当前状态，是不同条件。
2. 比较的是可验证的发言/确认来源时刻与稳定来源顺序，不是这次处理时间，也不是句中所说事情发生的时间。本人今天明确纠正过去事实，属于新的确认，应仍可按原合同纠错。
3. 不能只按 `source_ingest_seq` 判断事实新旧：来源重新分类、附件变化等会重新入扫描，旧发言不因此变成新确认。QQ 平台来源也须明确可信顺序，时间未知/冲突不自动覆盖已确认当前状态。
4. 旧材料不统一丢弃。可以保留历史及合规同命题证据，但不据此复活已完成/取消事项或替换更晚确认的当前值；历史纠错与当前状态变更分开核验。必要时保守拒绝当前变更、保留待核对依据。
5. 不把 completed/cancelled 做成永久不可改变：真实较新的重新开始或取消纠正仍应允许。保留原目标快照、逐字证据、去重和 sourceGuard，不用新顺序检查替换旧保护。

必要回归：让较早真实后处理先网络失败、较新任务完成后再重试；旧任务用新读目标快照仍不能回滚当前事实或完成/取消状态。另测相同事实的旧证据可保存、较新真实重启可更新、今天纠正过去仍有效、事件描述时间与发言时间不同、未知时间、相同时间稳定顺序、重新入扫描、跨 QQ/App 来源和存档恢复。

## 其余定点核对及实施安排

- 记忆页“旧版本”项实际只展示 history 图标，不提供普通恢复按钮；本轮没有把通用 `setMemoryStatus` 可调用直接算成用户可点出的“错误复活”漏洞。
- 旧目标快照/源消息版本/同源重放已存在保护；R5 专门覆盖旧来源新读目标的边界，不把已有保护说成不存在。
- QQ 私聊近期日志、全局新上下文/存档身份及合法历史的边界仍按 R2 和阶段 A 适配；本轮不把首版只读、独立短期历史的既定范围另算旧漏洞。
- 图片文字保留、混合私密摘要、来源/权限过滤在 LIMIT 前、后台成长直接读表等继续沿第一轮方案，未据重复阅读再加编号。

执行顺序更新为 A0 定向修 R1–R5，再在 A 做来源/范围/用途、存档、统一检索（O1）、受限写回与跨入口续聊；之后保持 B–E。每项先补真实入口受控回归，再做共享模块原调用者检查；本轮没有开启代码或 CI/APK，G1–G7 继续后移。

# 双通道感官：AI → 自身回响（v0.32.1+53）

日期：2026-08-15  
状态：已实现，等待 CI 与真机验收  
数据库 schema：21（本轮不变）

## 目标

在原有“用户动作 → 她的身体感觉”之外，补齐第二方向：

- 她在回复正文中**实际做出的身体动作**，可以反馈成自己的短时身体感觉；
- 强度按同类用户动作的 **0.5 倍**进入感官聚合；
- 只影响下一轮及之后的语气、注意力、动作选择和联想；
- 不把内部数值报告给用户，也不突破 Session、规则层、主动消息或私房语料边界。

## 写入时机与原子性

AI → 自身事件使用 assistant message ID 作为 `turn_id`，事件 ID：

```
{assistant_message_id}:ai_to_self:{scene_key}
```

动作检测本身是纯计算；真正写入与以下内容处于同一个 SQLite transaction：

1. assistant 消息落库；
2. generation job 从 running 变为 completed；
3. AI → 自身 somatic event 写入；
4. somatic aggregate 合并。

因此以下情况不会留下“幽灵触感”：

- 用户停止生成；
- 流式连接未完成、空正文或格式失败；
- 网络失败与等待重试；
- run token 已过期；
- transfer lock / Active Brain 权限变化；
- 旧 writer 或恢复任务重复执行。

任何一步抛错都会整体回滚；稳定事件 ID 与唯一键继续负责幂等。

## 识别边界

首版只覆盖触觉，并采用保守的第一人称完成动作/动作括号识别：

- 牵手、拥抱、亲吻；
- 抚摸、轻拍、轻捏、揉动；
- 依偎轻蹭、倚靠、轻挠、轻咬。

明确过滤“想、准备、打算、如果、没有、不、不会、不能、差点”等意图、假设与否定前缀。没有命中时保持沉默，不为覆盖率强行制造感觉。

## 数据与提示词边界

- `direction = ai_to_self`
- `source = assistant_committed`
- `channel = touch`
- 事件生命周期与衰减沿用 v0.32.0：半衰期 8 分钟、最长 36 分钟；
- prompt 阈值 0.18，最多输出 2 条自然语言身体感觉；
- 不改 schema，不新增长期存档，不写入记忆库或私房 corpus；
- 取消/撤回用户 turn 时，原有 user → AI 事件仍按外键级联撤回。

## 验收建议

1. 她实际回复“（抱住你）”后，下一轮应可能受到拥抱余感影响；
2. 她只说“我想抱住你”时，不应产生 AI → 自身事件；
3. 回复完全完成前点停止，不应出现 assistant 消息或对应感官事件；
4. 同一 durable job 恢复/重复运行，不应产生第二条同 ID 事件；
5. 诊断中可看到 `direction=ai_to_self`、`source=assistant_committed`，且同类强度约为 user → AI 的一半。
